# Трекер полного перепроектирования интерфейса курса

Последнее обновление: **4 сентября 2026 года**.

## Цель

Создать масштабируемый учебный симулятор рабочего места бизнес-аналитика: реальная рабочая среда компании, внутри которой встроены объяснение, практика, помощь и маршрут обучения.

## Неизменяемые требования

1. Светлый и понятный интерфейс для компьютера без визуального шума.
2. Задачи, сообщения, документы, данные, встречи и учебные материалы находятся в одной согласованной среде.
3. На каждом этапе видны текущее действие, его смысл и следующий переход.
4. Интерактивность меняет способ работы ученика, а не только оформление экрана.
5. Постоянные иллюстрированные персонажи вводятся постепенно и не противоречат сценарию.
6. Интерфейс поддерживает уровни «Стажёр → Junior → Middle» и новые проекты.
7. Помощник Codex доступен из любого учебного состояния.
8. Старый интерфейс удаляется только после принятия и проверки замены; учебное содержание не удаляется.

## Подтверждённая модель оболочки

```text
Рабочий компьютер
├── стабильный рабочий стол
├── отдельные приложения
│   ├── задачи
│   ├── почта
│   ├── корпоративный чат
│   ├── документы и база знаний
│   ├── таблицы и данные
│   ├── диаграммы
│   └── календарь и встречи
├── учебный маршрут
└── переход в живой чат-помощник Codex
```

### Правило первого запуска приложения

1. Объяснить простыми словами, что это за инструмент и зачем он аналитику.
2. Показать основные области экрана без перегрузки терминами.
3. Разобрать одно действие на рабочем примере.
4. Провести ученика через первое действие с подсказками.
5. Дать похожее самостоятельное действие.
6. Оставить постоянную справку и возможность спросить помощника.

### Адаптация подсказок

- `Ведение`: система показывает последовательность действий и объясняет каждое из них.
- `Поддержка`: система показывает цель и ближайший шаг, но не готовый способ решения.
- `Самостоятельность`: обычные подсказки скрыты; доступны запрос помощи и справка.
- Переход между режимами определяется выполненными заданиями и качеством переноса навыка, а не временем в интерфейсе.

## Подтверждённая модель окон

- знакомая метафора Windows;
- отдельные перемещаемые окна;
- панель задач и рабочий стол;
- постепенное открытие приложений;
- виджеты календаря, задач, уведомлений и состояния проекта;
- рабочая логика профессиональных инструментов без буквального копирования их оформления;
- простые рисованные аватары постоянных сотрудников.
- вход через GitHub и синхронизация прогресса через отдельное хранилище;
- сохранение положения, размера и состояния окон;
- настоящие названия профессиональных продуктов при явной маркировке учебных имитаций;
- спокойный фон с ненавязчивой иллюстрацией компании;
- без звуков уведомлений;
- допустимые педагогически обоснованные срочные события.

## Контракт с отдельным помощником

Создан чат `Помощник курса — объяснить непонятное`, thread id `01a067ac-19ae-7ba2-8d98-81103a666fc3`.

Новая оболочка должна сохранять в общем состоянии как минимум:

| Поле | Что передаётся помощнику |
|---|---|
| `level` | стажёр, Junior или Middle |
| `project` | текущий клиентский проект |
| `session` | занятие или рабочий день |
| `screen` | открытое приложение и окно |
| `task` | текущая задача простыми словами |
| `step` | текущий этап учебного маршрута |
| `attempts` | сделанные попытки без скрытого эталона |
| `opened_material` | изученная теория и справка |
| `help_mode` | ведение, поддержка или самостоятельность |
| `last_update` | время последней синхронизации |

Главный сценарий — помощник читает состояние автоматически. Скриншот используется, если состояние устарело, экран содержит визуальную проблему или ученик хочет указать на конкретный элемент.

## Приватность и синхронизация

- публичный код отделён от приватных данных ученика;
- вход выполняется через GitHub, состояние хранится в отдельном защищённом хранилище;
- синхронизируется полный учебный контекст и положение окон;
- поддерживается ограниченная офлайн-работа с последующей отправкой изменений;
- конфликт двух устройств не разрешается молчаливой перезаписью;
- доступна полная резервная копия;
- в Miro попадают утверждённые конспекты и результаты, но не черновики и личный журнал ошибок;
- помощник не получает пароли и посторонние данные настоящих сервисов.

## Правило разнообразия

Формат знакомства с новым приложением не становится форматом всех уроков. Библиотека сценариев должна включать теорию до действия, теорию после попытки, расследование, входящее сообщение, наблюдение за коллегой, встречу, симуляцию, разбор ошибки, работу с документами, построение схемы и анализ последствий.

## Главный фильтр интерфейса

```text
Компетенция → понятное объяснение → осмысленная практика →
обратная связь → исправление → самостоятельный перенос → повторение
```

Порядок и внешний формат могут меняться, но элементы учебного цикла не исчезают. Рабочая сцена, игра, окно или персонаж без конкретной учебной функции удаляются или переводятся в необязательный атмосферный слой.

## Учебный слой внутри рабочего компьютера

| Элемент | Подтверждённое поведение |
|---|---|
| Учебный маршрут | Показывает всю программу, зависимости и развитие до Middle |
| Рабочая задача | Сначала отображается как настоящая задача без учебной подсказки в её тексте |
| Панель обучения | Показывает скрытую от рабочего документа учебную цель и ближайший шаг |
| Обязательная теория | Простое объяснение, которое нельзя незаметно пропустить |
| Углубление | Книги, видео, стандарты и дополнительные примеры, проходимые частями |
| Реальная лаборатория | Выводит ученика в настоящие Jira, Miro, Excel и другие инструменты |
| Срочное событие | Появляется только на безопасной границе учебного действия |
| Конспект | Автоматически собирает изученное, ошибки, повторение и артефакты с последующим переносом в Miro |
| Общий прогресс | Показывается процентами; подробности раскрываются до уровня навыков |
| Время истории | Сюжетное, не зависит от реальной паузы между занятиями |
| Оценка времени | Показывается перед действием как ориентир активной работы |
| Свободное исследование | Открытые приложения доступны вне текущего маршрута |
| Ошибка | Либо безопасное последствие и исправление, либо остановка до критичного ущерба |
| Возвращение | Краткая сводка места остановки и кнопка «Вернуться к работе» |
| Уведомления | Без звука; значки, счётчики и центр уведомлений |
| Развитие рабочего стола | Новые приложения, проекты, документы, команда и результаты появляются постепенно |
| Мобильный режим | Теория, сообщения, конспект, прогресс и помощник без сложной многооконной практики |
| Медиасообщения | Голосовые сообщения, записи встреч и видео персонажей |
| Рабочие показатели | Показываются только при содержательной связи с проектом |
| История решений | Хранит выбор, доказательства, последствия и исправления |

## Первый запуск профессионального инструмента

```text
Полноценный учебный материал
        ↓
Роль инструмента в работе аналитика и команды
        ↓
Безопасная песочница со сбросом
        ↓
Настоящий сервис в новой вкладке
        ↓
Пошаговое рабочее задание из панели обучения
```

До завершения обязательного материала первая практическая задача в новом инструменте недоступна. После освоения инструмент может использоваться в любых подходящих сценариях без повторения полного введения.

## Окно учебного материала

```text
┌────────────────┬──────────────────────────────┬──────────────────┐
│ Содержание     │ Объяснение                  │ Текущий шаг      │
│ темы           │ Видео                       │ Прогресс         │
│                │ Интерактивная схема         │ Время            │
│ Закладки       │ Демонстрация                │ Помощник Codex   │
│ Заметки        │ Короткое упражнение         │                  │
└────────────────┴──────────────────────────────┴──────────────────┘
```

Обязательные функции:

- сочетание разных медиа по учебной необходимости;
- выделение, закладки и личные заметки;
- вопрос помощнику по выделенному фрагменту с автоматическим контекстом;
- проверка понимания перед песочницей;
- короткие ссылки рядом с утверждением и полный список источников;
- восстановление раздела, раскрытых элементов, упражнения и момента видео.

## Рабочие задачи

| Ситуация | Поведение системы |
|---|---|
| Источник задачи | Jira, письмо, Teams, встреча, срочное событие или комментарий в документе |
| Неполный запрос | Требует уточнить заказчика, цель и ожидаемый результат |
| Рост сложности | Одна задача на старте, затем несколько параллельных задач |
| Карточка Jira | Реалистичные поля, связи, вложения, комментарии и критерии готовности |
| Завершение | Передача рабочего артефакта и реакция получателя |
| Конфликт приоритетов | Требует согласования с руководителем |
| Командная доска | Показывает зависимые задачи и состояние работы других ролей |

## Обратная связь и доказательство роста

| Элемент | Поведение |
|---|---|
| Реакция компании | Сначала ответ сотрудника или заказчика внутри сюжета |
| Учебный разбор | Затем отдельная оценка преподавателя |
| Критерии | Заранее видны в учебной панели, но не подменяют рабочую формулировку |
| Последствия | Сохраняются и при необходимости создают задачу на исправление |
| Процент прогресса | Может снижаться после забывания или неудачного переноса |
| Повторная тренировка | Доступна отдельно и не переписывает основной сюжет |
| Журнал ошибок | Личный, скрытый от персонажей, с планом повторной проверки |
| Портфолио | Автоматически хранит лучшие артефакты и историю версий |

Вход через GitHub

- Все инструкции по интерфейсу можно повторить в справочном центре.

## Коммуникации и встречи

| Элемент | Подтверждённое поведение |
|---|---|
| Содержательный ответ | Свободный текст или голос ученика |

## Поле сравнительного исследования

### Образовательный опыт

- русские программы бизнес-аналитики;
- международные профессиональные сертификаты;
- интерактивные платформы, хорошо показывающие маршрут, практику и прогресс.

### Рабочий опыт

- системы постановки и ведения задач;
- корпоративные коммуникации;
- базы знаний и документы;
- аналитические рабочие пространства.

Маркетинговые обещания курса не считаются доказательством качества интерфейса. В аудит попадают только наблюдаемые экраны, переходы и механики; недоступные части честно отмечаются как непроверенные.
